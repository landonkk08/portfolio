# Portfolio OS

A portfolio site styled as a custom desktop operating system. It uses plain HTML, CSS and JavaScript: no build step and no dependencies.

## Files

| File | What it is |
|---|---|
| `js/data.js` | **All your content.** Edit this file to change your name, bio, projects, skills and links. |
| `index.html` | The desktop experience (on phones it switches to a phone-style layout). |
| `plain.html` | The plain, scrollable view for recruiters, linked from the taskbar and the "Plain view" icon. |
| `css/styles.css` | All styles. Colors and fonts are set at the top as variables. |
| `js/app.js` | Boot screen, windows, taskbar and the Settings window. |
| `js/settings.js` | Visitor settings (theme, accent, wallpaper, motion, sound), saved in their browser. Accent presets live here. |
| `js/wallpaper.js` | The animated wallpapers: drifting lights, topographic, starfield and plain gradient. |
| `js/sound.js` | Interface sounds, generated in code (no audio files). |
| `js/plain.js` | Builds the plain view from `data.js`. |
| `privacy.html` | The privacy policy page. Its text lives in `js/privacy.js`, which the desktop's Privacy window also uses. |
| `terms.html` | The terms and conditions page. Its text lives in `js/terms.js`, which the desktop's Terms window also uses. |
| `css/fonts.css` | Self-hosted fonts (files in `assets/fonts/`, with their open-source licences). |
| `404.html` | The "File not found" page GitHub Pages shows for missing addresses. |
| `assets/` | Favicon, home-screen icon and link-preview image. |
| `sitemap.xml`, `robots.txt` | For search engines. Generated by `tools/update-meta.mjs`; don't edit them by hand. |
| `js/secret.js` | The Secret app's message, encrypted. Generated by `tools/encrypt-secret.mjs`; don't edit it by hand. |
| `tools/` | Pages and scripts that generate the PNG images in `assets/`, `js/secret.js`, and the page titles and descriptions. Not part of the live site. |
| `.githooks/pre-commit` | A check that blocks commits containing keys, passwords or local-only files. |

## Adding your content

1. Open `js/data.js` and replace each placeholder.
2. Put images in an `assets/` folder, e.g. `assets/projects/my-game.png`, and set `image: "assets/projects/my-game.png"`. A 16:10 ratio works best. With `image: null` the site shows a generated cover in the project's `color`: pixel tiles for games, code lines for software and overlapping shapes for design, behind the project's first letter. Each project's pattern is different but always the same for that project (it's based on the `id`), so changing a project's `id` reshuffles its pattern. The patterns are drawn in `PATTERNS` in `js/covers.js`.
3. Pick your best project for the **Featured** card with `featured: "project-id"` in `js/data.js`. The card sits at the top-right of the desktop and below the icons on phones, and clicking it opens that project. If the id doesn't match, the first project is shown; `featured: null` hides the card. On short desktop screens (under 620px tall) it's left out so it doesn't crowd your name.
4. **No projects yet?** Leave `projects: []`. The Projects window and the plain view then show the `projectsEmpty` message from `js/data.js`, with a "Visit my GitHub" button if you have a GitHub link, and the featured card is hidden. A commented-out template above `projects` shows every field for your first one.
4. Save your resume as `assets/resume.pdf`, then set `resume: "assets/resume.pdf"` in `js/data.js`. While it's `null`, the Resume icon, window, menu entry, Alt+R shortcut, `#resume` link and plain-view link are hidden, so visitors never hit a missing file.
5. Optional: add `video: "https://www.youtube.com/watch?v=VIDEO_ID"` to a project to show a clip in place of the cover. Any YouTube link format works, and it's embedded in privacy-enhanced mode (youtube-nocookie.com).

   Videos are **click-to-load**, which is the site's cookie consent: the project's cover shows with a play button and a note that the video plays from YouTube, and nothing is fetched from YouTube until the visitor clicks Play. After one click, other videos load straight away until the tab is closed. That's why the site needs no cookie banner. If you ever add analytics or another service that sets cookies, you'd need to ask for consent before it loads.

## Previewing locally

Open `index.html` in a browser, or run a small local server from this folder:

```powershell
python -m http.server 8080
```

Then visit http://localhost:8080.

The boot screen plays once per browser tab. Close the tab or clear session storage to see it again.

As the boot screen fades, the desktop **reveals** itself in about 1.2 seconds: the wallpaper fades in, the icons drop in one by one, your name types itself with an amber block cursor, then your role, the featured card and the taskbar slide in. Any click, tap or key press finishes it instantly (and still does what it normally would). It only plays after the boot screen, never on reloads, and not at all when motion is off. The timings are in `reveal()` in `js/app.js`.

## Settings app

Visitors can change the theme (System, Light or Dark), the accent color, the wallpaper, motion and sounds. Choices are saved in their browser.

- The theme follows the visitor's device until they pick one.
- Motion follows their device's "reduce motion" setting until they change it.
- Sounds are on by default, but browsers keep pages silent until the first click or key press.
- **Reset to defaults** acts straight away, then shows "Settings reset. Undo" for 8 seconds.
- To change the accent presets, edit `ACCENTS` in `js/settings.js`. `onLight` is a darker version of the color, used for text on the light theme.

## Keyboard shortcuts

Hold **Alt** (**⌥ Option** on Mac) and press a key. **Alt+/** shows the full list. The shortcuts are off on phones.

| Keys | Action |
|---|---|
| Alt+P, A, S, C, R | Open Projects, About me, Skills, Contact, Resume (R only once a resume is set) |
| Alt+, | Open Settings |
| Alt+[ and Alt+] | Previous / next window |
| Alt+M | Minimize the front window |
| Esc | Close the front window |

The list is `SHORTCUTS` in `js/app.js`.

## Secret app

Clicking (or tapping) your name on the desktop 5 times quickly opens a hidden window. It can't be opened with a link.

Its message is stored encrypted in `js/secret.js`, so it can't be read by searching the site's files or the GitHub repo. To change it:

1. Edit `tools/secret.local.json` (copy `tools/secret.example.json` if it's missing). This file stays on your PC: Git ignores it, so keep your own backup.
2. Run `node tools/encrypt-secret.mjs`. It rewrites `js/secret.js`.
3. Commit `js/secret.js`.

This only hides the message from casual snooping. The key is in the site's code, so a developer who digs in can still read it. Never put anything private there.

## Keeping secrets out

Everything in this repo is public: anyone can read it on GitHub, and every visitor's browser downloads the site's files. So:

- **Never put an API key, token or password in the site's code.** A static site can't keep anything hidden. If you ever need a service that requires a key, call it from a small server or proxy (for example a serverless function), never from these files.
- **Git ignores local secret files**: `.env` files, `*.pem`/`*.key` files, SSH keys, a `secrets/` folder and anything named `*.local.*`. See `.gitignore`.
- **A pre-commit check** (`.githooks/pre-commit`) blocks a commit that adds those files, or lines that look like a known key format (AWS, Google, OpenAI, Stripe, GitHub, Slack, private keys) or an assignment like `apiKey = "..."`. It's switched on once per copy of the repo with:

  ```
  git config core.hooksPath .githooks
  ```

  If it blocks a commit, remove the secret from the file and the commit, then try again. If a real key was ever committed, treat it as leaked: revoke it with the service that issued it, then remove it.
- **GitHub can check too.** In the repo on GitHub, open Settings → Code security and turn on **Secret scanning** and **Push protection**. They catch keys even when a commit skips the local check.

## Icons, link previews and the 404 page

- **Favicon:** `assets/favicon.svg` (the Lantern OS logo), with PNG fallbacks `assets/favicon-32.png` and `assets/apple-touch-icon.png` for phone home screens.
- **Logo on the site:** the boot screen, taskbar and 404 page draw the same lantern in CSS (`--lantern` in `css/styles.css`), so it follows the visitor's accent color. If you change the shape, update `assets/favicon.svg`, `tools/icon.html` and `--lantern` together.
- **Link-preview image:** `assets/og-image.png` (1200×630), designed in `tools/og-image.html`. It shows your OS name, name, role and `siteUrl` from `js/data.js`, plus the generated covers of your first four projects.
- **After changing your name, role or OS name**, regenerate the images (needs Microsoft Edge):

  ```powershell
  powershell -ExecutionPolicy Bypass -File tools\make-images.ps1
  ```

  Then run `node tools/update-meta.mjs` to update the page titles and descriptions (see below).
- **404 page:** `404.html` is shown by GitHub Pages for any address that doesn't exist. It assumes the site lives at `/portfolio/`. If you rename the repository, change `repo` in its first script (and the URLs in the `og:` tags).

## Page titles and descriptions

Each page's title (browser tabs, search-result headlines) and description (the text under it in search results and link previews) come from `meta` in `js/data.js`. `{name}` and `{role}` in them are filled in from `owner`.

Search engines and link-preview sites (Discord, LinkedIn, iMessage...) read the HTML without running JavaScript, so the text also has to be written into each page. After changing `meta`, your name or your role, run:

```powershell
node tools/update-meta.mjs
```

It updates the `<title>`, `description`, `og:title` and `og:description` tags in `index.html`, `plain.html`, `privacy.html` and `terms.html`, plus the title of `404.html`, and warns if a title or description is too long to show in full. Keep titles under about 60 characters and descriptions under about 155.

On the desktop, the browser tab title follows the window in front (for example "Example Game One · Your Name"), using `meta.windowTitle`, and goes back to the main title when no window is focused.

## Search engines

The same script, `node tools/update-meta.mjs`, also writes two files from `siteUrl` in `js/data.js`. Run it again whenever `siteUrl` changes.

- **`sitemap.xml`** lists the four public pages: the desktop, plain view, privacy policy and terms. `404.html` is left out.
- **`robots.txt`** lets every crawler in, blocks the `tools/` folder, and points to the sitemap.

**While the site lives in a subfolder** (like `https://<your-username>.github.io/portfolio/`), search engines don't read `robots.txt`: they only look for it at the root of the domain. The script warns about this. The file is kept so it works as soon as the site moves to the root, either with your own domain or by renaming the repository to `<your-username>.github.io`. If you rename it, also update `siteUrl` and `repo` in `404.html` (see above), then run the script.

Until then, tell Google about the sitemap yourself:

1. Open [Google Search Console](https://search.google.com/search-console) and add a property of the **URL prefix** type, with your full `siteUrl`.
2. Verify that you own it. The **HTML tag** method gives you a `<meta name="google-site-verification" ...>` tag: paste it into the `<head>` of `index.html`, commit, push, wait a minute, then click Verify.
3. Go to **Sitemaps**, enter `sitemap.xml`, and click Submit.

For Bing, [Bing Webmaster Tools](https://www.bing.com/webmasters) can import the site straight from Search Console.

## Privacy policy

The policy is in `js/privacy.js`, and it's shown at `privacy.html` and in the desktop's Privacy window. It's linked from the taskbar, the OS menu, the phone home screen, the plain view and the 404 page. It fills in your name and email from `js/data.js`, and it only mentions YouTube if a project has a video.

It describes what the site does now: no cookies or analytics, settings saved only in the visitor's browser, GitHub Pages hosting and self-hosted fonts. **If you add anything that collects data or loads content from another service** (analytics, a contact form, comments, another embed), update the text and `LAST_UPDATED` at the top of the file. This is a plain-language policy for a personal site, not legal advice.

## Terms and conditions

The terms are in `js/terms.js`, and they're shown at `terms.html` and in the desktop's Terms window, linked everywhere the privacy policy is. They say:
- All rights are reserved for your work and for the site's design and code. Visitors may browse and share links, but not copy or reuse anything without permission.
- There's no warranty, and your liability is limited.
- There's no governing-law clause.

The copyright year updates automatically. If you later license your code (e.g. MIT) or some of your work (e.g. Creative Commons), update the terms and `LAST_UPDATED` to match. This is a plain-language template for a personal site, not legal advice.

## Deploying to GitHub Pages

1. Create a GitHub repository. Name it `<your-username>.github.io` for a site at `https://<your-username>.github.io`, or use any name for `https://<your-username>.github.io/<repo-name>`.
2. Push these files to the `main` branch.
3. In the repository, go to **Settings → Pages**, set **Source** to "Deploy from a branch", and pick `main` and `/ (root)`.
4. Wait about a minute, then open the URL GitHub shows.
5. On the same **Settings → Pages** screen, tick **Enforce HTTPS**. (If you add your own domain, the box only becomes available once GitHub has issued its certificate, which can take up to a day.)

### HTTPS

The site is meant to be served only over HTTPS. Two layers make sure of that:

- **GitHub's Enforce HTTPS setting** (step 5 above) is the main one. GitHub redirects every `http://` visit before the page loads.
- **A backup in every page's `<head>`** (`index.html`, `plain.html`, `privacy.html`, `terms.html`, `404.html`): a short script that redirects `http://` to `https://`, and a `upgrade-insecure-requests` tag that makes the browser fetch any `http://` image, font or script over HTTPS. The redirect is skipped on `localhost`, so local previews keep working. If you add a new page, copy those lines into its head.

Always use `https://` links for images, videos and other files you add.
